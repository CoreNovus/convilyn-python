# What has been measured

This page reports test results for the three things this package does with
documents: **convert offline**, **convert on the platform**, and **extract
structured data**. It reports nothing else — no roadmap, no comparison against
other tools, no claim that is not a number produced by a run.

Every figure comes from **[`doc-eval`](https://github.com/CoreNovus/doc-eval)**,
a separate evaluator with no model, no network and no API key in its scoring
path. It is deterministic: the same prediction files scored twice give the same
numbers. The corpora are named and versioned, so a reader can re-run them.

Measured 2026-08-28, with the `doc-eval` code released as **0.2.0**.

The evaluator version is named because scores move when it changes, and this
round is an example: `date_iso` gained English month-name folding, which
corrected one field of the 10-K case below from a false miss to a pass without
the platform's answer changing at all. Scoring the same predictions with 0.1.0
gives a lower number for that case. Reproduce with 0.2.0 or later.

## The corpora

| corpus | what it is | documents | scored | network |
|---|---|---|---|---|
| `synth-v1` | 25 generated documents — 6 document kinds × up to 8 formats × 3 locales (en, ja, zh-TW), each with a golden Markdown written from the same declaration that writes the document | 25 | 25 conversions + 3 extractions | not needed |
| `wild-v1` | 3 real published documents — the W3C XML 1.0 (5th ed.) specification, Apple's FY2023 Form 10-K, and a CC-BY arXiv paper. Gold is hand-authored assertions, verified against the fetched bytes | 3 | 3 conversions + 1 extraction | required |
| `olmocr-textual-v1` | the four **textual** slices of [olmOCR-Bench](https://huggingface.co/datasets/allenai/olmOCR-bench) (AI2, ODC-BY-1.0), imported complete | 657 | 2,583 assertions | required |

`synth-v1` needs no network and is rebuilt from source on demand, so it is the
one anybody can reproduce with no external dependency.

## 1. Offline conversion — `convilyn local convert`

Runs entirely on your machine. No account, no key, nothing uploaded.

**`synth-v1`, 20 of 25 documents.** The 5 it does not attempt are the HTML
inputs: this engine has no HTML reader at all, and refuses rather than guessing
(`Unsupported conversion: No route from html to md`).

| | |
|---|---|
| Deterministic assertions | **100.0%** (n=20) |
| Corpus assertions | **99.3%** (n=20) |
| Normalised edit distance to the golden Markdown | **0.9634** (n=20) |
| Table structure — TEDS / TEDS-Struct | **0.9196 / 0.9333** (n=10) |
| Heading tree — F1 | **0.9091** (n=11) |
| Reading order | **1.0000** (n=8) |
| Inline formatting — F1 | **1.0000** (n=20) |

**`olmocr-textual-v1`, 657 real-world PDFs.** 650 converted; 7 failed to
convert. Overall corpus assertions: **36.5%**.

That headline is not a fair summary of the engine, and the reason is worth
stating rather than burying: **145 of those 650 pages have no text layer at
all** — a median of 24 extracted characters, i.e. they are page images. This
engine does not do OCR, by design. Split on that:

| | pages | assertions passed |
|---|---|---|
| pages that have a text layer | 505 | **41.4%** |
| pages that are images only | 145 | 13.5% |

Within the pages that do have a text layer, the ordering of the output was
measured directly, as the share of the PDF's own adjacent word-pairs that are
still adjacent in the produced Markdown:

| | median |
|---|---|
| control — the `wild-v1` arXiv paper (3,238 words) | 85.4% |
| control — a `synth-v1` two-column PDF | 94.7% |
| olmOCR `multi_column` (14 docs) | **86.8%** |
| olmOCR `headers_footers` (15 docs) | **84.0%** |
| olmOCR `long_tiny_text` (11 docs) | **64.9%** |

So ordinary multi-column layout measures at the control's level. **Dense,
small-type pages — dictionaries, newspapers, dense reference works — are where
the output degrades**, and it degrades by re-ordering, not by losing text: on
those pages the word count still matches the PDF's text layer at 1.00×, and
every heading anchor on the page inspected appeared exactly once in both. Of
214 failing "must contain" assertions on pages that have a text layer, 107 are
strings present in the PDF but absent from our Markdown, and all 107 are on
that page class.

| Heading tree — F1 | **0.9375** (n=16) |
| Reading order | **1.0000** (n=11) |
| Inline formatting — F1 | **1.0000** (n=25) |

**`wild-v1`, 3 of 3 real published documents** — a 1.5 MB SEC filing, a W3C
specification, and an arXiv paper: deterministic assertions **100.0%** (n=3),
corpus assertions **100.0%** (n=3), reading order **1.0000** (n=3).

**Offline and platform output are the same bytes.** On every case both paths
can read — 20 `synth-v1` documents plus the `wild-v1` arXiv paper, 21 in
total — the two outputs are byte-for-byte identical. The offline engine is not
a reduced local approximation of the hosted one; for the formats it supports it
is the same engine.

## 3. Structured extraction — `convilyn goals understand`

Returns JSON conforming to a JSON Schema you supply. Scored on two axes that
are deliberately never averaged together, because their fixes are opposite:
**inventing a value for a field that is not in the document**, and **refusing
to answer a field that is**.

**`synth-v1`, 3 documents / 16 fields** (an invoice as DOCX, the same invoice as
PDF, and a zh-TW receipt as PDF). Each declares one field that is *not* in the
document — a tax id — so abstention is what is being tested.

| | |
|---|---|
| Field accuracy — micro-F1 | **1.0000** (n=16) |
| Text fields — ANLS | **1.0000** |
| Normalised-exact fields (dates, currency) | **1.0000** |
| List fields — set-F1 | **1.0000** |
| **Inventing on an absent field** | **0.0%** (n=3) |
| **Refusing a field that is present** | **0.0%** (n=13) |

The zh-TW receipt is included in that: vendor `美廉社股份有限公司`, the three
line items, and a date written `2026年6月30日` normalising to `2026-06-30` were
all extracted correctly.

**`wild-v1`, 1 document — Apple's FY2023 10-K, 5 fields.** A real 1.5 MB SEC
filing. The absent field here is the total audit fee, which a 10-K does not
disclose (it is in the DEF 14A proxy) — chosen because it *sounds* like it
belongs in the document, which is the only kind of absent field that tests
anything.

| | |
|---|---|
| Field accuracy — micro-F1 | **1.0000** (n=5) |
| Text fields — ANLS | **1.0000** |
| Normalised-exact fields | **1.0000** |
| **Inventing on an absent field** | **0.0%** (n=1) |
| **Refusing a field that is present** | **0.0%** (n=4) |

Company name, state of incorporation, total net sales (383,285 million) and the
fiscal year end were all correct, and the audit fee was correctly left out. The
filing writes its year end as **September 30, 2023** and that is what came back;
the corpus stores `2023-09-30`, and the evaluator folds the two spellings onto
the same date.

### One current defect, and how to avoid it

**A nullable field written as a union — `{"type": ["number", "null"]}` — can
make the run fail, and it is still charged.** The union is narrowed to
non-nullable before the model sees it, so a model that correctly declines to
invent the value has no legal way to say so; its answer is then rejected. That
is what happened on the first attempt at the 10-K case above.

**Declare an optional field by leaving it out of `required`, not by adding
`null` to its type.** With `auditor_fee_total` declared as plain
`{"type": "number"}` and absent from `required`, the same document, same field,
same platform returned the table above: the model omitted the key and the run
succeeded. Both forms mean "this may be absent" in JSON Schema; only the second
currently survives the round trip.

## What is not measured here

- **Images, audio and video.** `doc-eval` scores documents. The image, audio
  and video conversions this package exposes are covered by other tests, not by
  the numbers above.
- **Latency and throughput.** No timing claim is made.
- **Any comparison to another product.** olmOCR-Bench is used here as a source
  of hard real-world pages, not as a leaderboard: it is an OCR benchmark, and
  the offline engine does not do OCR.
- **Mathematical content.** olmOCR-Bench's two mathematics slices (3,385 tests)
  are excluded by `doc-eval` itself, which scores no LaTeX equivalence.

## Reproducing this

```bash
pip install "doc-eval @ git+https://github.com/CoreNovus/doc-eval"

doc-eval build-corpus synth-v1          # no network
doc-eval fetch-corpus wild-v1           # 3 documents
doc-eval fetch-corpus olmocr-textual-v1 # 657 documents

# produce one <case-id>.md per document with whichever path you are testing,
# then:
doc-eval run --pred ./predictions --corpus synth-v1
```

`doc-eval corpora` lists what is available and whether each is cached.
